Install and get started

Do the machine setup once. Initialize Bob separately inside each application repository.

Show commands for
1
ONCE PER MACHINE

Clone Bob

Clone the private repository through your normal GitHub authentication, then enter the folder.

git clone https://github.com/latentBinary/Bob.git cd Bob
2
ONCE PER MACHINE

Install the terminal command

uv builds Bob in an isolated tool environment and makes bob available from other folders.

uv tool install .
If your shell cannot find bob
Run uv tool update-shell once, then open a new terminal.
3
ONCE PER APPLICATION

Initialize your application

Move into your application repository. Bob checks readiness, shows the exact plan, and asks before writing.

bob doctor --agent codex bob init --agent codex
Then open the repository in Codex and invoke $bob-init.

05

What Bob protects

Bob makes its own installation bounded and reviewable. Your coding agent and operating system remain the ultimate enforcement layer.

◎

Approval first

Initialization stages changes elsewhere, prints every managed target, and writes only after an explicit yes.

◇

Your work stays yours

Unrelated custom skills, application Markdown, project tracking, and optional vault notes are preserved.

↶

Recoverable changes

Bob writes atomically, records hashes last, and either rolls back a failure or names every unresolved path.

⌁

Pinned foundation

Spec Kit v1.0.2 is used at its reviewed immutable commit. Bob does not silently follow a moving release.
